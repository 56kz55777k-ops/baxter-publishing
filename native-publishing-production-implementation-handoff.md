# Part 1 — Executive implementation position

**What Spike C v2 proved.** Every interaction that defines the editor, to acceptance: the spread as the editing coordinate system with pages as the print boundary; one creation language across five element types; dependable multi-selection; magnetic snapping across creation, drag (union-box), resize (moving-edges-only, preview == commit mathematically), and line endpoints; a cursor system that predicts the action before mousedown; publication-scale text editing (2,000+ words) through a viewport-clamped overlay with one-commit-per-session semantics; an inspector that behaves as one designed system with a watertight numeric contract; locked-object rules; and mode transitions (Clean View, Review Book) that preserve the creator's place to the pixel. Konva's suitability for this interaction vocabulary is proven at prototype scale (~2,000 objects/page at ~7 ms/draw, Spike C), including the two architectural discoveries worth preserving verbatim: the **outer-wrapper/inner-Konva cursor ownership boundary** and the **screen-px↔mm conversion contract for Transformer boxes**.

**What it deliberately did not prove.** Persistence beyond localStorage; multi-user or multi-tab behaviour; asset pipelines (its images were data URLs); font strategy (it measured Georgia/Helvetica stand-ins, *not* the production Fraunces × DM Sans); PDF export from the editor scene graph (Spike B proved the exporter stack separately, on a scene shape the editor serializes to — but the two spikes never ran end-to-end in one process, and Spike B's code was lost to a scratchpad wipe with its conclusions locked); print overflow semantics (deliberately open); performance beyond one spread at a time; accessibility; mobile.

**Why the prototype is interaction-complete.** Five consecutive acceptance reviews closed every open interaction concern on Ben's list, each with measured evidence and a preserved baseline (source snapshot + audit + demonstration player per review). The remaining backlog items are polish (Part 14), not interaction questions. Further prototype work would refine throwaway code.

**Why production should begin now.** The risk has inverted: the unknowns are no longer "how should it feel" (answered) but "how does it live in the production architecture" — persistence, concurrency, assets, fonts, export — none of which the prototype can answer. Every additional prototype pass now buys nothing the production slices wouldn't buy better.

**Recommended sequence.** Slices A–J (Part 11), aligned with the repo's own M2 scope: document shell first (schema + load/save/revision + empty spread), then shapes+selection, then movement/snapping, resize, images, crop, text, lines, viewing modes, hardening. Export (M2.4) remains a separate later phase behind an explicitly decided overflow contract (Part 10).

**Standing rule:** **Spike C v2 is a behavioural specification, not production code.** Port contracts and algorithms deliberately; copy no file wholesale. The prototype remains available at `~/Desktop/baxter-spikes/spike-c2/` with per-review snapshots for arbitration when a contract question arises.

# Part 2 — Accepted interaction contracts

Consolidated and final. Format per system: **Intent · Entry · Behaviour · Commit · Cancel · History · Autosave · Cursor · Locked · Edges · Accepted-in.** (Autosave in the prototype = debounced localStorage after any commit; production translation in Part 7. "R#" = the review that accepted it; systems accepted before Review 9 are marked "pre-R9 baseline" — they were locked in Passes 1–8 and re-verified continuously through R9–R13.)

**1 · Publication & spread coordinate model.** Intent: think in pages/spreads, not canvas. A publication = cover (single) + interior pages paired into spreads (verso|recto) + back (single). All geometry in **millimetres**, top-left origin **relative to each page's trim**; both facing pages render in one spread-space (page 2 at `x + trimWidth`). Typography in **points** (`PT_MM = 25.4/72`). Model values live on a 0.01 mm grid (see #19/#24 for the one historic exception). Content clips at the spread's bleed boundary — nothing spills onto the pasteboard. Pre-R9 baseline; precision grid refined R9/R12.

**2 · Page ownership & cross-gutter objects.** Intent: objects flow across the gutter freely; print still needs one owning page. Every element belongs to exactly one page; its `x` may be negative or exceed the page width (spanning the gutter). **Re-parenting happens only on drag-drop**, to the page the object's *centre* lands on. **Resize never re-parents** (stretching across the gutter keeps ownership; the inspector shows a negative page-relative X). Accepted R9 (resize rule), pre-R9 baseline (drop rule).

**3 · Creation language.** Intent: one grammar for every tool. Rect/ellipse/image/text/line: tool armed → crosshair (text tool: I-beam) *before* mousedown → click shows an anchor dot → drag shows live preview + size readout pill (`W × H mm`; line: `length mm · angle°`, Shift constrains angle) → creation snaps to the shared target set with oxblood guides → release creates the element, selects it, arms the inspector, returns to Select (image opens the file picker; text enters editing with the placeholder selected so typing replaces it) → click-away finishes. Tiny drag (<3 mm) = click = default-size element. Guides/pill vanish at release. History: one entry per created element. Pre-R9 baseline; placeholder-selection refined R11.

**4 · Selection & primary selection.** Intent: selection is dependable. Click selects; click empty space deselects; selection is a set of element ids; the single-selection object drives the inspector. Selection survives undo/redo (restored with each history entry, filtered to still-live ids — **stale ids are never recreated**), tool changes where reasonable, and both viewing modes. Transformer shows resize handles for a single unlocked non-line object; hidden while a creation tool is armed (selection persists underneath). Pre-R9 baseline; mode survival R13.

**5 · Multi-selection.** Intent: work on groups without grouping. Shift-click toggles membership; ⌘A selects everything on the current spread (locked members included — selectable, not mutable). Multi shows a dashed border only (no handles). Inspector: "N objects · M locked" header; shared editable property (opacity) applies to **unlocked members only, in one history action**; mixed values show an **em dash — never a fabricated average**; delete removes unlocked members only and says so. Accepted R9 (union move), R12 (inspector semantics).

**6 · Marquee.** Intent: select by area, calmly. Drag on empty page/pasteboard draws a quiet dashed rectangle; releases selects all elements whose bounds intersect; Shift-marquee adds to the existing set; a <2 mm drag is a click (deselect). Cursor stays default throughout — stable while crossing objects. Pre-R9 baseline; cursor rule R10.

**7 · Object drag.** Intent: move one or many as one rigid body. Dragging any selected member moves every unlocked member by the shared delta; per-member drop re-parents by centre; **one history entry** via a single batched commit (`applyMoves`). Locked members neither move nor block the rest. During drag the cursor is `move`, held across anything the pointer crosses. Drag commits round to **0.1 mm** (historic grid — retained deliberately, see #19). Pre-R9 baseline; union snapping R9; cursor R10.

**8 · Snapping (creation, drag single+multi).** Intent: magnetic, not controlling. Target set = page edges, page centre-lines, margins, plus every *other* element's edges and centres (text elements contribute their **measured rendered height**, not a width-based guess). Snap radius **1.6 mm**; nearest target within radius wins; thin oxblood guide lines render while a snap is engaged and vanish at release. Drag snapping evaluates the **union bounding box of the whole moving set** (edges + centre) — a single object is a union of one, so single and multi share one code path. Magnet dynamics: engages within radius, releases cleanly past it — verified engage/hold/release. Accepted R9.

**9 · Transformer resizing.** Intent: resize with the same snapping language, exactly. Handles on a single unlocked non-line element (text: width handles only). Konva Transformer boxes arrive in **absolute screen px** (the Transformer ignores ancestor transforms); convert `mm = (px − view.x|y) / zoom`. **Only the edges the gesture moves may snap** (detected by diffing newBox vs oldBox per edge — robust to ratio locks, centred scaling, and Konva's flip anchor-renaming); fixed edges are provably pinned (every model value sits on the 0.01 mm grid, so quantizing a fixed edge is an identity). The bounded preview box is stored and **the commit writes exactly those numbers** — preview == commit mathematically, no post-release jump. Full box commits: x, y, w, h (text: x + width only). Anchor-click without movement commits nothing — no history entry. Live `W × H` pill (width-only for text) shares the creation readout. Cursor: Konva's directional, angle-aware anchor cursors, untouched (see #21). Accepted R9.

**10 · Ratio lock.** Intent: constrained resize that never fights snapping. ⇧ or the Ratio toggle; corner anchors only (Konva applies no ratio on side anchors). Under ratio, snapping computes candidates on both moving axes, picks the single best |correction|, converts it to **one scale factor applied to both axes** pinned at the fixed corner — ratio preserved exactly (to the 0.01 mm commit quantization, ≈0.007% worst case, a model-wide property). Minimum size outranks the snap (factor floored; guide dropped honestly). Accepted R9.

**11 · Minimum sizes.** Intent: clamps that can never cause a release jump. Minimums enforced **during preview**, pinned to the fixed edge (text ≥ 10 mm width; shapes/images ≥ 4 mm per axis; inspector floor W/H ≥ 2 mm — see #19 note). Frames already below minimum are grandfathered: they can't shrink further but never pop up at gesture start. Flip disabled; dragging through the minimum freezes at the last good box. **Accepted edge case (drag-through):** if the user keeps dragging far past the minimum, Konva renames the anchor and the gesture resumes from the opposite edge — commit still equals preview. **Ben's recorded preference if ordinary use ever surfaces it: hold at the minimum until mouseup and require a fresh gesture from the opposite edge.** Do not change it pre-emptively. Accepted R9 (+ the design note).

**12 · Image frames.** Intent: **frames remain frames; contents change.** An image element is a frame (x/y/w/h) plus content state: `src`, natural dimensions, `fit: fill|fit`, `cropZoom` (1–3×), `focal {x,y}` (0–1). Fill crops from the focal point; Fit letterboxes on the frame's fill colour. Replacing the image preserves the frame and its identity (same element id). Empty frames render an invitation ("double-click to add image") and open the picker on double-click. During resize the content visibly stretches and re-crops at commit (live re-crop is deferred polish, Part 14). Pre-R9 baseline; resize interplay R9.

**13 · Crop mode.** Intent: adjust content, not the frame. Double-click a filled image enters crop; dragging pans the **content** (focal point) inside the fixed frame; crop-zoom lives in the inspector; a hint pill explains; Esc exits keeping the frame selected. Focal commits are live during the pan (each drag-end = one commit). Cursor: `grab` over the content, `grabbing` while panning, default elsewhere — the vocabulary of moving content, not frames. **Viewing-mode entry exits crop cleanly** (no stroke, no hint, no reopen on return — the frame is simply selected). Pre-R9 baseline; cursors R10; mode exit R13.

**14 · Text frame creation.** Intent: type immediately. Creating a text frame (drag or click-for-default) enters editing at once with the placeholder fully selected — first keystroke replaces it. Width-only geometry (height is always the rendered text height; the model stores no text height). Accepted R11.

**15 · Long-form text editing.** Intent: publication-scale writing with no awareness of the canvas/DOM boundary. Double-click enters editing **at the clicked caret position** (line from the canvas text engine's own wrap data; column by prefix measurement; clicked passage scrolled to mid-view). The editor is an overlay matching the frame's width/font/size/leading exactly (wrap parity measured: 1 wrap point drift in 214 lines on the stand-in fonts — re-verify on production fonts, Part 8) but is its **own presentation layer**: high-contrast ink, oxblood caret, warm panel, regardless of publication colours; publication styling restores exactly on exit. **Height-managed**: hugs content (min ~3 lines), grows while typing, clamps to the visible workspace; long documents scroll *inside* the editor — the publication never pans while writing. If the frame head is above the viewport the editor pins near the workspace top (width/wrap unchanged; access outranks alignment). Input is uncontrolled: typing/paste/in-session undo are native and never touch the document model. **Commit: on blur (click-away, Esc, ⌘Enter, mode entry) — once per session, and only if the text changed**; unchanged sessions leave zero trace. Keyboard isolation: Space/⌘A/Backspace/Delete/tool letters/arrows belong to the text while editing. IME: composition guarded (`isComposing` — Escape never commits mid-composition). Retained limitations (accepted, do not fix silently): occasional one-word wrap drift at engine boundaries; 15% zoom editable but impractical; Tab exits via native focus movement; live IME/press-and-hold/emoji expected-but-unverified; **overflow semantics deliberately open** (Part 10). Accepted R11.

**16 · Line creation.** Intent: lines are vectors, not rectangles. A line is `(x,y)` plus a `(width,height)` delta to its endpoint (either may be negative). Creation: anchor → live line preview with endpoint dots → `length · angle` readout → Shift constrains to horizontal/vertical/45° → endpoint snapping. Hit area is generous (`hitStrokeWidth ≥ 6`). Pre-R9 baseline.

**17 · Line endpoint editing.** Intent: edit the vector, never a bounding box. A selected line shows two endpoint handles (no Transformer). Dragging an endpoint previews a dashed ghost, snaps to the shared target set **plus the other endpoint's axes**, shows guides, and commits exactly the previewed geometry (commit == preview). Cursor: crosshair on endpoint hover/drag, outranking the line body's `move`. Pre-R9 baseline (mechanics), R9 (commit parity), R10 (cursors).

**18 · Inspector.** Intent: the primary editing surface; one designed system. Contextual: page (nothing selected) / single object (Position & Size or line Endpoints → type section → Appearance → Arrange → Lock) / multi (shared + lock-all + delete). Token system: one 14 px inset (no control touches a panel edge — beware the `<fieldset>` min-content quirk, fixed by `fieldset { min-width: 0 }`); 26 px field height across inputs/selects/segments/swatches/slider rows/arrange buttons; 30/26/20 px button scale; one radius, border, background; one restrained oxblood focus ring; disabled = fieldset-driven, default cursor, never `not-allowed` as decoration. Stroke model: **None is first-class** — distinct from thin; setting a width activates the stroke with a default colour; picking a colour assigns a default width; width 0 returns to None. Terminology: shapes say Fill/Stroke/Stroke width; text ink is Colour; Size is labelled in points (suffix outside the editable text); geometry is implied-mm everywhere (units written nowhere except read-only page settings — consistent by absence). Accepted R12.

**19 · Numeric controls.** Intent: typing and stepping agree about everything. Buffered text fields (`inputMode=decimal`): while focused, the draft string is free — empty, "-", "12." are never parsed, committed, or clamped. Commits on blur / Enter (keeps focus) / each arrow press; invalid drafts restore the last valid value; clamps only at real declared bounds (X/Y/endpoints unbounded — negative page-relative values are first-class; W/H ≥ 2; size ≥ 4 pt; leading ≥ 0.8; stroke ≥ 0 shapes / 0.1 line; radius/crop ≥ 0). Every typed-reachable bound is step-reachable. Arrows: ±step (fine fields ±0.1), Shift ×5 (fine ±1); each press = one deliberate history entry. Escape restores and exits the field without touching canvas selection. No-op visits and identical-value commits create nothing. Display = model exactly, ≤2 dp, trailing zeros stripped, −0 normalised. **No native spinners** (accepted; no permanent +/- controls without a new decision). **Precision contract:** inspector and resize commit at 0.01 mm; **drag/creation/nudge commit at 0.1 mm** — the one historic cross-system difference, retained deliberately (do not "fix" without a decision). Note: the inspector's W/H floor (2 mm) is below the resize minimum (4 mm) — grandfathering in #11 absorbs this; carry the inconsistency knowingly or reconcile it as a conscious production decision. Accepted R12.

**20 · Locked objects.** Intent: locked means untouchable, not invisible or unselectable. Locked elements: selectable (border, 🔒 badge, inspector identity + Locked banner + Unlock), draggable never, resize handles never (border remains), excluded from every property mutation (`patchAll` skips them structurally; the lock property itself is the single permitted mutation via a dedicated path), excluded from delete/duplicate/nudge/moves, **included as snap targets**. Cursor over locked: neutral default — selection is honest; never `not-allowed` as a hover state. Multi: locked members counted in the header, skipped by edits, one-action lock-all/unlock-all. Pre-R9 baseline; handles R9; cursor R10; mutation guarantees R12.

**21 · Cursor resolver.** Intent: the cursor predicts the action before mousedown. **Approved architecture — preserve:** one resolver derives the cursor from interaction state and writes it (layout-effect, pre-paint) to the **outer wrapper element**; Konva's Transformer keeps writing its directional, angle-aware anchor cursors to the stage's **inner content element** — inner wins while set and inherits back the instant it clears. Two owners separated by CSS containment; no race is possible; never replace Konva's anchor-cursor mechanism. Priority: Clean View (grab/grabbing while panning, else default) → text editing (textarea owns its native I-beam; canvas reads default) → crop (grabbing/grab-over-content/default) → object drag (`move`, held) → marquee (default, stable) → active pan (grabbing) → hand available (grab, outranks hover) → creation tools (crosshair; text tool I-beam; stable through the whole gesture) → endpoint gesture/hover (crosshair, outranks body) → object hover (`move` unlocked / default locked — **hover state stores only the element id; lock state is looked up live**, so lock toggles update the cursor without pointer movement) → default. Platform-standard cursors only; zero custom cursors. Window blur clears all transient cursor state; Escape/tool switches/Clean View never leave stale cursors. Accepted R10.

**22 · Clean View.** Intent: judge the spread; the publication is the hero. **The same continuous viewport with chrome removed; strictly view-only.** Entry (Tab or toolbar): the workspace widens by the navigator width and the view compensates by exactly that amount — **the spread does not move on screen (0.0 px, both directions)**; navigator/inspector hide; guides, pills, marquee, drafts, gesture flags, hover clear; **crop exits**; selection state, tool, history, autosave untouched — entering is never an edit. Active text editing commits once through the ordinary blur path before toolbar entry lands; Tab inside any field is focus movement, never a mode switch. Inside: pan (wheel/Space) and zoom only; **every mutation stands down, including undo/redo** (accepted; revisit only on concrete hands-on need). Tab or Esc returns. Exit: **one pan state — panning done while viewing becomes the editing viewport**; selection, primary selection, inspector, tool exactly as left; only still-valid selection restores. Accepted R13.

**23 · Review Book.** Intent: read the publication as a reader. A full-screen modal reader stepping cover → spreads → back, fit-to-view per unit, prev/next + ← → Space + counter + Exit + Esc. **Fully modal to the keyboard: nothing reaches the document, selection, or tool while open** (the app-level key handler stands down entirely); paging creates no history; render is true publication rendering (no chrome, no handles). Exit returns to the **originating editing spread and viewport** — never the page last read — selection, inspector, and tool intact; no text/crop submode reopens. Reader navigation and editing navigation are separate concepts. Accepted R13 (contract), pre-R9 baseline (surface).

**24 · Undo/redo boundaries.** Intent: one intention = one entry. History is a document-state stack; each entry stores the document plus the selection set (restore filters to live ids). One entry per: element creation; drag session (however many members); resize gesture; endpoint move; crop pan (per drag-end); inspector commit (typed value or single arrow press); slider change; text session (only if changed); delete; duplicate; paste; nudge press; lock toggle; page/spread operation. Zero entries for: selection changes, tool changes, viewing-mode toggles, hover, anchor-clicks, no-op commits, unchanged text sessions, invalid input. In-text-session undo is the browser's native text undo; document undo takes over after commit. Viewing modes block undo (see #22/#23). Accepted R9–R13 cumulatively; this is the union.

**25 · Autosave boundaries.** Intent: work is never lost, saving is never an event. Prototype semantics to preserve: autosave follows *commits* (debounced ~400 ms), never keystrokes, never mode changes, never selection; no save can exist without a history entry having existed. Production translation in Part 7 (revision-guarded, status-window-aware). Pre-R9 baseline; verified through R13.

**26 · Keyboard shortcut isolation.** Intent: keys mean what the focused surface means. Global (canvas focus): V/H/T/I/R/L tools; ⌘A select-all-on-spread; ⌘Z/⇧⌘Z; ⌘C/X/V; ⌘D duplicate; Delete/Backspace; arrows nudge 0.5 mm (Shift 5 mm); Space momentary hand; Tab Clean View; Esc deselect + Select tool. Any INPUT/TEXTAREA/SELECT focus: the app handler stands down entirely (typing guard) — text and field semantics are native. Review Book open: everything stands down. Clean View: only Tab/Esc/Space(+zoom) live. Window blur clears Shift/Space modifier state. Pre-R9 baseline; R11 (field isolation verified), R13 (mode guards).

**27 · Pan & zoom.** Intent: the workspace is a continuous surface. Two-finger scroll pans; pinch/ctrl+wheel zooms about the pointer (0.15–8× of the 3.4 px/mm base); Space or H drags to pan (grab/grabbing); Fit Page / Fit Spread / 100% buttons; auto-fit on spread navigation and window resize — never on mode toggles. The view is ephemeral state (never persisted, never history). Wheel over the text editor scrolls text, never the spread; canvas pan during text editing moves the editor in lockstep. Pre-R9 baseline; mode continuity R13.

# Part 5 — Recommended production domain model

**Recommendation: a new `editor_documents` table, 1:1 with publications** (the scope doc's option A). Not a JSONB column on `publications` (that row is contended by marketplace saves, RLS-narrowed, and audit-logged for status transitions; mixing a high-frequency scene graph into it couples autosave to unrelated writers and bloats every publication read). Not R2-JSON (no RLS, no queryability, no atomic revision check). Follow the house migration convention (hand-written idempotent SQL; journal untouched).

```sql
-- 0007_editor_documents.sql (hand-written, applied via Supabase SQL editor)
CREATE TABLE IF NOT EXISTS editor_documents (
  publication_id uuid PRIMARY KEY REFERENCES publications(id) ON DELETE CASCADE,
  doc            jsonb  NOT NULL,          -- the scene graph, shape below
  schema_version integer NOT NULL DEFAULT 1,
  revision       integer NOT NULL DEFAULT 0,  -- optimistic concurrency; increments on every accepted save
  updated_at     timestamptz NOT NULL DEFAULT now(),
  updated_by     uuid REFERENCES users(id),
  autosave_state jsonb                      -- { lastClientId, lastSavedAt } — diagnostics only, never authority
);
-- RLS: select own-or-admin; insert own while parent draft/revisions; update own while parent draft/revisions
-- (mirror publications_update_own_draft's window exactly; no client DELETE).
```

**`doc` shape (jsonb), v1** — the prototype model, typed and hardened:

| Field | Slice-A requirement | Notes |
|---|---|---|

# Part 7 — History and autosave architecture

**Transaction boundaries (one history entry, then one autosave schedule):** exactly the #24 list. Client-side implementation: reducer actions `commit(docNext, selectionNext, label)` — snapshot-based history is acceptable initially (the prototype's JSON snapshots handled realistic spreads without measurable cost; revisit with a structural-sharing or patch model only if profiling at M2.3 page counts says so — Risk 9). History cap: bounded entries (e.g. 100) + drop-oldest; document this to Ben before beta.

**Previews live locally, always:** drag positions, resize boxes, crop pans, text drafts, inspector drafts — the model mutates only at the commit boundary (this is the accepted architecture; it is also what makes autosave trivial to reason about).

**Autosave pipeline:** commit → mark dirty → debounce (recommend 1.5–2 s of commit-quiet, max-wait 10 s; the prototype's 400 ms is too chatty for a network + middleware round-trip) → `POST /api/editor/[id]/save { doc, schemaVersion, baseRevision, clientId }` → server: auth + ownership + **status ∈ {draft, revisions}** (mirror RLS; fail with a distinct code otherwise) → conditional write `UPDATE editor_documents SET doc=…, revision=revision+1, updated_at=now(), updated_by=… WHERE publication_id=… AND revision = baseRevision` → returns `{revision}` or **409 {serverRevision}**.

- **Stale revision (409):** the only expected cause today is a second tab (single-editor product; no collaboration architecture — the existing product implies none). Contract: the losing tab goes read-only with the calm banner ("This publication was edited somewhere else — reload to continue") and offers reload; **never silent last-write-wins, never auto-merge.** Do not build CRDTs.
- **Save failure (network/5xx):** keep dirty, retry with backoff (10 s, 30 s, 60 s), status line shows the existing quiet language escalating only on repeated failure ("Baxter can't reach the shelf — your work is safe in this tab"); editing continues.
- **Navigation away / tab close:** `beforeunload` guard only while dirty-or-saving; attempt a final `keepalive` save. **Local recovery (IndexedDB mirror): not required for Slice A**; add as a hardening item (Slice J) if beta shows real loss windows — record it as an explicit decision, not an accident.
- **Status window edge:** if the publication leaves the editable window while the editor is open (admin action elsewhere), the next save's distinct error flips the editor to read-only with the situation explained. The editor loads only when status ∈ {draft, revisions} and says why otherwise.
- Autosave never fires from mode toggles, selection, or no-op sessions — impossible by construction (it keys off commits).

# Part 8 — Font and text-rendering production risks

The prototype measured **stand-in fonts** (Georgia/Helvetica via CSS) against Konva's canvas renderer and achieved 1-wrap-point-in-214-lines parity **on those fonts**. Production type is **Fraunces × DM Sans loaded via `next/font/google` — for which the repo holds no font binaries.**

**Required before first production text editing (Slice G):**
- **Self-host the editor's font files** (licensing check first; D-006's DIN question attaches here). One set of font binaries must feed *all three* consumers: CSS (`@font-face`/next-font local), canvas measurement/rendering (Konva), and eventually PDF embedding. This is the single decision that makes "perceptual continuity" portable.
- **Font readiness:** the editor must await `document.fonts.load()` for its faces before first paint of text nodes and before any measurement (`textArr`, caret mapping, snap targets from text heights). The prototype never handled this; cold-cache production will.
- **Re-run the parity measurements** (wrap counts, caret mapping accuracy, editor-overlay alignment) on the real faces. Expect the drift class to persist (two engines), not worsen; do not promise pixel identity; keep the R11 honest-drift language.
- **Fallback policy:** if a face fails to load, block text *editing* (not viewing) with the quiet situation line, rather than measuring against a fallback font and committing geometry-affecting text state.

**Required before PDF export (M2.4, later):** embedding via `@pdf-lib/fontkit` (to be added — currently absent) using the same self-hosted files; subset embedding; selectable text (Spike B proved all of this on its stand-ins); export-side line breaking must be **the editor's own wrap data, serialized** — never a re-wrap by a third engine (this is the convergence contract's sharpest edge; validate with a golden-doc round-trip: editor render vs mupdf-rendered export preview, pixel-diff within tolerance).

**Safe to defer:** optical kerning niceties; variable-font axes (Fraunces is variable — decide static instances at the font-file step and be done); hyphenation (excluded — plain wrapping only); RTL/vertical text (out of product scope today, note only).

**Unicode/IME:** carry the R11 position verbatim — standard-compliant uncontrolled textarea, `isComposing` guarded, accents/dashes/quotes verified, live IME expected-but-unverified until a hands-on native-input pass. **Overflow:** Part 10 — the editor must *measure* overflow (rendered text height vs page bottom) and expose it as state from Slice G, even while print semantics stay open.

# Part 9 — Image pipeline integration

Map editor image frames onto the existing machinery with one honest addition: **the current upload path is PDF-only** (`api/upload/r2-presigned` hard-rejects other content types). Editor images need either a widened presign route with per-purpose validation or (recommended) a **parallel `api/editor/assets/presign`** endpoint — same presign helper, image-specific rules — leaving the print-file path untouched.

- **Upload:** presigned PUT to quarantine (`editor-assets/<publicationId>/<uuid>-<sanitized>`), content-type allowlist (`image/jpeg`, `image/png`; decide TIFF/WebP explicitly), size cap (decide; suggest 50 MB). Browser PUT direct, as today.
- **Validation/processing (new small Inngest function, following `publication-preflight`'s shape):** load bytes → verify actual magic bytes match claimed type → extract pixel dimensions (+ DPI metadata if present; pixels are the truth that matters — printed DPI = pixels ÷ placed size, computable per placement) → generate an editor preview derivative (Cloudflare Images upload, existing helper; new variant if the current `cover/full` don't suit — account-level change, note it) → promote original to clean → write the `assets` row: `kind: 'editor_image'`, `provider: 'r2'` for the original + `meta { px: {w,h}, previewImageId, bytes, contentType }`. **No AV exists in the pipeline today (recon §6): flag to Ben as a product decision, since editor images broaden the input surface beyond PDFs — do not silently claim scanning.**
- **Asset identity:** documents reference `assets.id` only. Naturals live server-side in `assets.meta`; the client never dictates them. **Frames remain frames; contents change** — replace = new assetId on the same element id; the frame geometry, fit, zoom and focal reset policy follows the prototype (focal resets to centre on replace).
- **Editor loading:** previews render from Cloudflare delivery URLs (public variants — decide whether editor previews may be public like today's page previews, or need the signed-URL variant flow; publication previews are already public, so public previews are consistent — originals stay private in R2 with presigned GETs only at export).
- **Missing/failed assets:** a frame whose asset row is gone or whose processing failed renders the calm placeholder state with its situation line (Constitution voice), stays selectable/movable, never crashes the document. Processing status = `assets.meta.status` (pending/ready/failed) polled or refreshed via the existing `router.refresh()` idiom until ready.
- **Permissions:** `assets` RLS today is SELECT+INSERT only for clients — replacement/cleanup writes go through server routes with the established admin-behind-a-guard pattern (or new narrow policies; decide at Slice E, prefer server routes to keep parity with the artifacts pattern).
- **Cleanup/orphans:** documents reference assets loosely; deletion of an element doesn't delete its asset (undo must restore it). Add a Slice-J orphan sweep (assets with `kind='editor_image'` unreferenced by their publication's current doc **and** older than N days), modelled on the D-014 retention sweep.
- **Export resolution:** export embeds from the R2 *original*, never the preview; per-placement effective DPI = asset pixels ÷ placed mm (through cropZoom), checked against the preset's `minImageDpi` at the export boundary (this finally makes the domain's dpi warning reachable).

# Part 10 — Export and preflight boundary (define now, build later)

**What the editor must guarantee to M2.4:** the document carries preset id (→ trim), resolved margins, page order/kinds; all geometry in mm on the 0.01 grid; z-order = element order; cross-gutter objects owned by one page but geometrically spanning (the exporter clips per page box — an element extends across the gutter by rendering on its owning page's spread coordinates and being clipped by each page's bleed box; the accepted spread model makes this deterministic); image placements reference clean-bucket originals with server-known pixels (per-placement DPI computable); text elements carry role→font-file-resolvable typography and (at export time) the editor's serialized wrap lines; lines/vectors as stroked paths; colours as the stored sRGB values (CMYK/ICC conversion is an exporter concern — **PDF/X remains explicitly NOT claimed**, per Spike B: no OutputIntent/ICC until the MGS calibration lands); page boxes MediaBox/TrimBox/BleedBox from preset trim + 3 mm bleed (Spike B-proven); clipping semantics: bleed box is the render clip.

**Preflight relationship:** *born-correct-but-still-inspected* stands — editor output lands in R2 quarantine as an artifact and runs the unchanged pipeline (dimension/count checks will pass by construction; the dpi warning becomes reachable once the exporter reports real image DPI; preflight stays the single quality gate for uploads and editor output alike).

**The deliberately unresolved decision — printed meaning of overflowing text.** Today (accepted interim): the canvas renders all text, clipped at the spread's bleed boundary; snap targets and marquee use full rendered height. Plausible print contracts: **(a) clip at the frame's page (bleed box)** — matches today's screen exactly; risks silently printing amputated sentences; **(b) clip at the frame** — requires frames to *have* heights for text (a model change; today text height is rendered, not stored); **(c) block export while any overflow exists** — safest print outcome; needs the editor's overflow measurement + a Constitution-voiced situation, and makes overflow a hard authoring error; **(d) auto-grow pages/flow** — threaded text, explicitly out of scope. **Decision point: before Slice G ships text *persistence*** (the doc model must not accidentally encode (b)), and **finally at M2.4 design** — the exporter cannot be written without it. Owner: Ben, with a demo of (a) vs (c) on a real overflowing spread. Until then the editor measures and *reports* overflow state but attaches no judgement.

**Warning/error model at the boundary:** reuse the domain's reason-code style (blocking vs warning, situation-not-status copy); preset validation (page-count bounds, ×4) surfaced live in the editor (M2.3 scope) but *enforced* only at submission, as today.
